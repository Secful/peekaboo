What is Peekaboo?

Peekaboo is a real-time API crawler and security scanner. It uses a headless browser to navigate a target website, intercepting network traffic, discovering API endpoints, enumerating subdomains, and identifying security issues — all from a single domain input.

Key capabilities:

  • Discovers web API endpoints by intercepting live network requests and analyzing page source
  • Enumerates subdomains and resolves their geolocation, technology stack, and open ports
  • Detects and analyzes Android APKs to extract mobile API endpoints
  • Discovers OpenAPI/Swagger specifications from public Git repositories
  • Evaluates HTTP security headers across all discovered hosts
  • Runs agentic AI analysis on subdomains for deeper security insights

Getting Started

Starting a Scan

When you first open Peekaboo, a start form appears asking for a target domain. Enter the domain you want to scan (e.g. example.com) and click Start Scan. The crawler will begin navigating the site and intercepting API traffic immediately.

Advanced Settings

Click Show Advanced Settings in the start form to configure:

Max Pages Maximum number of pages to crawl (default: 50).
Max Depth How many link-levels deep from the start page to follow (default: 3).
Timeout Per-page navigation timeout in seconds (default: 30).
Proxy Optional HTTP/SOCKS proxy URL for the browser to route traffic through.
Concurrent Pages Number of browser tabs to run in parallel (default: 3).
Fast Mode Skip screenshots and reduce per-page interaction for faster scans.

API Filter Options

Before starting a scan, you can choose which API traffic to capture:

  • All — Capture every intercepted request (default).
  • Target Domain Only — Only capture requests to the target domain and its subdomains.
  • External Only — Only capture requests to third-party domains.

Dashboard Layout

The dashboard is divided into three main areas:

Top Bar

Contains the Peekaboo logo, domain indicator showing the current scan target, scan control buttons (Pause, Current Findings, Terminate, New Scan, History, Help), and a live status badge showing the current scan state.

Left Panel

  • Stats Grid — Real-time counters for Total APIs, Domain APIs, Pages crawled, Hosts discovered, and Queue size, plus a scan timer.
  • Live Preview — A thumbnail of the page the crawler is currently visiting. After the scan completes, this area shows a summary with a "Create Report" button.
  • Activity Log — A scrolling log of crawler events and APK analysis progress (see Activity Log).

Right Panel

Contains tabbed views for all discovered data. The primary tabs are Web Endpoints and Subdomains. Additional tabs (Mobile Endpoints, OpenAPI Specs) appear dynamically when relevant data is discovered during the scan.

Web Endpoints Tab

This is the default tab and the primary view for discovered API endpoints. It has three sub-views accessible via toggle buttons: APIs, Service Mesh, and Headers.

API Table

The main table lists every intercepted API endpoint. Click any row to open the detail drawer with full request/response information.

Columns

ColumnDescription
#Row number in the current page.
MethodHTTP method (GET, POST, PUT, PATCH, DELETE). Color-coded.
PathThe URL path of the endpoint. Long paths are truncated with a tooltip showing the full value.
HostThe hostname the request was sent to.

Filters

  • Domain — All / Subdomain / External.
  • Method — Filter by HTTP method. Buttons appear dynamically as methods are discovered.
  • API Type — All / API (confirmed) / Maybe / Not API.
  • Status — All / 2xx / 3xx / 4xx / 5xx / No Status.
  • Search — Free-text filter across path and host.

Detail Drawer

Click any table row to slide open the detail drawer on the right. It shows the full URL, request/response headers, query parameters, body content, API classification details, and detection metadata.

Service Mesh

A D3 force-directed graph that visualizes the relationships between the target domain and all discovered services/hosts. Each node represents a host, and edges represent API communication paths observed during the scan. You can drag nodes to rearrange the layout.

Tip
The service mesh updates in real time as new hosts are discovered. It’s a great way to understand the overall architecture of a web application at a glance.

Headers Analysis

A heatmap view of HTTP security headers across all discovered hosts. Each row is a host, and each column is a security header (e.g. Content-Security-Policy, Strict-Transport-Security, X-Frame-Options). Cells are color-coded:

  • Green — Header present with a secure configuration.
  • Yellow — Header present but with a weak or partial configuration.
  • Red — Header missing.

Click any cell to see the finding details, including a link to the relevant MDN documentation.

Security Findings

The second sub-tab within Headers Analysis. Peekaboo automatically evaluates every response from the target domain against a set of security rules and reports findings grouped by severity.

Security Grade

A letter grade (A–F) is calculated based on the ratio of high-severity findings to total endpoints analyzed. The grade and severity chip counts are displayed at the top of the view.

Finding Cards

Each finding card includes:

  • Severity badge — HIGH, MEDIUM, LOW, or INFO.
  • Problem — What is wrong (e.g. “This API doesn’t enforce HTTPS connections”).
  • Impact — How an attacker could exploit it in plain language.
  • Fix — The recommended remediation with the exact header to add.
  • Attack flow diagram — A visual SVG diagram showing the attack chain step by step (click a card to expand).
  • Affected endpoints — The list of endpoints where this issue was detected.

Rules Checked

Tip
Click any finding card to expand it and see the attack flow diagram along with the full list of affected endpoints. This is useful for prioritizing remediation.

Subdomains Tab

Lists all subdomains discovered for the target domain. Subdomains are found via DNS enumeration, certificate transparency logs, and network traffic analysis.

Table View

The default view shows a card/table for each subdomain, including:

  • Status — Whether the subdomain is reachable (resolved, timed out, etc.).
  • Technology Detection — Identified web technologies and frameworks (pills).
  • Security Pills — Quick-glance security indicators (SSL status, header issues, etc.).
  • IP Address — Resolved IP address and ASN information.

Click the toggle to switch between Table and Map views.

Map View

A world map (Leaflet) showing the geographic location of each discovered subdomain based on IP geolocation. Markers are clustered and color-coded by status. Click a marker to see details about that subdomain.

Detail Drawers

Each subdomain has several detail drawers accessible via action buttons on the row:

  • APIs — All API endpoints discovered on that subdomain.
  • Security — Security insights including header analysis, SSL details, and vulnerability indicators.
  • Open Ports — Port scan results showing open services (when available).
  • Agentic — AI-powered deeper analysis of the subdomain’s security posture.
  • API Specs — Any OpenAPI/Swagger specifications found for that subdomain.

Mobile Endpoints Tab

Note
This tab appears dynamically only when Android application packages (APKs) are discovered during the scan.

When Peekaboo detects links to Android APKs on the target site, it automatically downloads and analyzes them to extract embedded API endpoints.

Android App Detection

A toast notification appears when an APK is detected. The APK is downloaded, decompiled, and analyzed for hardcoded API URLs, endpoints, and configuration data.

Endpoint Table

Similar to the Web Endpoints table, but specifically for mobile API endpoints. Filters include:

  • Domain — Filter by target domain or external.
  • App — Filter by which APK the endpoint was extracted from.
  • Category — Endpoint category (API, CDN, Analytics, etc.).
  • Status — HTTP status code filters (2xx, 3xx, 4xx, 5xx).

Traffic Testing

Peekaboo can send test requests to discovered mobile endpoints to verify they are live. Results include:

  • Status badges — Color-coded reachability indicators.
  • Confidence score — How confident the tool is that the endpoint is a real API.
  • Verification probes — Detailed probe results showing request/response data.

Detail Drawer

Click any row to open the detail drawer with full traffic test results. The drawer includes a verification probes section that shows:

  • WAF Detected — Indicates whether a Web Application Firewall was detected protecting the endpoint (e.g. Cloudflare, AWS WAF, Akamai). Highlighted with a distinct badge when present.
  • OPTIONS Allowed — HTTP methods permitted by the server’s OPTIONS response.
  • OPTIONS CORS — CORS headers returned by the OPTIONS preflight request.
  • Response Headers — A collapsible key-value table showing all HTTP response headers returned by the endpoint during the traffic test. Click to expand.

OpenAPI Specs Tab

Note
This tab appears dynamically only when OpenAPI/Swagger specifications are discovered in public Git repositories associated with the target.

Peekaboo searches public Git repositories for API specification files (OpenAPI 3.x, Swagger 2.0). When specs are found, they are parsed and displayed here.

Spec List

Shows each discovered spec file with its source repository, version, and the number of endpoints defined. Click a spec to drill down into its endpoints.

Endpoint Drill-Down

Lists all operations defined in the spec (method + path). Click any endpoint for a detail drawer showing parameters, request/response schemas, and authentication requirements as defined in the spec.

Scan Controls

The top bar contains the following control buttons (some appear only during active scans):

Pause / Resume Pauses the dashboard UI updates. The underlying crawler continues running — this only affects the real-time display.
Current Findings Opens a summary modal showing all findings discovered so far in the current scan.
Terminate Stops the crawler immediately. Discovered data is preserved and the scan is saved to history.
New Scan Resets the dashboard and opens the start form to begin a fresh scan.
History Opens a modal listing past scans. Click any past scan to load and review its results.
Help Opens this help page in a new tab.
Warning
Terminating a scan is irreversible for that session. The crawler stops and no further endpoints will be discovered. However, all data found up to that point is saved.

Activity Log

Located at the bottom of the left panel, the activity log has two tabs:

Activity Tab

A real-time stream of crawler events: pages visited, endpoints discovered, errors encountered, and status updates. Each entry is timestamped and color-coded by type.

APK Analysis Tab

Shows the progress of Android APK analysis when mobile apps are detected. Includes download status, decompilation progress, and endpoint extraction results.

Tip
The activity log auto-scrolls to the latest entry. You can scroll up to review past events — auto-scroll pauses while you are reading.

Scan Lifecycle

A scan progresses through several stages:

  1. Crawling — The browser navigates pages, intercepts network traffic, and discovers endpoints in real time. The live preview shows the current page and stats update continuously.
  2. Crawl Complete — All pages within the configured limits have been visited. The dashboard transitions from the live preview to a summary view.
  3. Waiting for External Analysis — Background tasks (subdomain resolution, port scanning, APK analysis, agentic analysis) may still be running. The status indicator shows when these are in progress.
  4. Done — All analysis is complete. The scan is automatically saved to history and a report can be generated.

Inactivity Timer

If no new endpoints or pages are discovered for 2 minutes, an inactivity bar appears in the left panel. When the timer fills completely, the scan auto-finalizes to prevent indefinite hanging on sites with no further content.

Scan Persistence

Completed scans are automatically saved and can be retrieved via the History button. Each saved scan preserves all endpoints, subdomains, mobile endpoints, and analysis results.
